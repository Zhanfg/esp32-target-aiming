# MST-01 失效模式分析（FAILURE_MODES.md）

本文件对应主规格 §33 交付项，记录机械、电气、固件三类的失效模式。每条按编号、失效模式、所属模块、
检测手段、系统响应、严重度、是否已有缓解组织。系统响应写清对应哪个 FaultCode 或哪条状态转移。

FaultCode 取自 `05_FIRMWARE/src/aim_types.h`：NONE=0、PERIPH_INIT=1、HOME_TIMEOUT=2、
HOME_SWITCH_CONFLICT=3、RELEASE_GATE_SELFTEST=4、OBS_LINK=5、INDEX_FAIL=6、WATCHDOG=7、
MECH_STUCK=8、ESTOP=9、MEMBRANE_RUPTURE=10、DOUBLE_FEED=11、FIRE_INHIBIT_SHORT=12、
I2C_BUS_HANG=13、STATE_ILLEGAL=14。软故障 HOME_TIMEOUT、OBS_LINK、INDEX_FAIL、WATCHDOG、
ESTOP、DOUBLE_FEED 可经 SAFE → HOME → READY 恢复；硬故障 PERIPH_INIT、HOME_SWITCH_CONFLICT、
RELEASE_GATE_SELFTEST、MECH_STUCK、MEMBRANE_RUPTURE、FIRE_INHIBIT_SHORT、I2C_BUS_HANG、
STATE_ILLEGAL 锁存，软件清除无效。

原先找不到对应 FaultCode 的失效模式已在枚举末尾补齐，逐个对照见第五节。
没有在线检测手段的条目单独标出，集中列在文末。

---

## 一、机械类

### FM-01 参考开关卡滞

- 所属模块：云台与供给盘（PAN_HOME、TILT_HOME、MAG_HOME）
- 检测手段：归零超时，3 秒内未触发或触发后丢失即失败；开关在三处 HOME 与门里的状态矛盾也能暴露部分问题。
- 系统响应：HOME_TIMEOUT(2) 或 HOME_SWITCH_CONFLICT(3) → FAULT → SAFE。释放链保持硬件断开，绝不进 READY。
- 严重度：高
- 是否已有缓解：有。参考开关加超时；故障锁存器复位条件接三处 HOME 开关的与，机构没真回零位就复位不了。

### FM-02 机构卡在中间态

- 所属模块：机械脉冲核心（STAGE_1、STAGE_2、膜片）
- 检测手段：MECH_RECOVERED 长时间为假；到位时间超时；STAGE1_STATE、STAGE2_STATE 与预期不符。
- 系统响应：MECH_STUCK(8) 硬故障，锁存；预载驱动使能由常闭触点物理断开；软件清除无效。
- 严重度：高
- 是否已有缓解：有。Interlock 1 用常闭干接点串在预载驱动使能里（架构 §6.5 H2）。

### FM-03 膜片破裂

- 所属模块：DIAPHRAGM_MODULE
- 检测手段：**无在线检测**。压力波形异常或气密性下降可在测试后看出，运行中靠人工目视与实验后检查。
- 系统响应：MEMBRANE_RUPTURE(10) 硬故障，锁存。目前无在线检测，靠人工检出后置位；操作者停止动作、更换膜片、记录，破裂导致的异常曲线在数据处理阶段剔除并复测。
- 严重度：中
- 是否已有缓解：部分。可拆压环便于检查与更换；§17 寿命检查含裂纹项。

### FM-04 弹性元件疲劳

- 所属模块：STAGE_1、STAGE_2 弹性片
- 检测手段：**无在线检测**。靠 force-displacement 漂移与 §17 寿命阶梯离线判断。
- 系统响应：无对应 FaultCode。寿命测试中记录漂移，超阈值停用该件。
- 严重度：中
- 是否已有缓解：部分。独立弹性元件便于更换；PET 做几何验证，弹簧钢做寿命版。

### FM-05 供给盘卡料

- 所属模块：MAGAZINE_MODULE
- 检测手段：index_detected 未在超时内到位；MAG_INDEX_OK 超时。
- 系统响应：INDEX_FAIL(6) 软故障；INDEX 状态内重试一次；连续失败或检出双片、错位则禁 Mode B、保留 Mode A；
  若卡在储能态且机构顶死，升级 FAULT 并保持硬件断开（架构 §6.8）。
- 严重度：中
- 是否已有缓解：有。单次重试加量化门槛，50 次人工复位不超过 1 次。

### FM-06 双片

- 所属模块：MAGAZINE_MODULE、PAYLOAD_MODULE
- 检测手段：**无专用传感器**。只能靠人工、视频或出膛异常发现；M1 里作为记录字段，不构成实时判据。
- 系统响应：DOUBLE_FEED(11) 软故障，检出后禁 Mode B；通过 CLEAR 清除，待修供给。
- 严重度：中
- 是否已有缓解：部分。旋转盘独立 pocket 降低叠片概率；§18 把 double_feed 列为记录项。

### FM-07 错位（载荷未对齐）

- 所属模块：MAGAZINE_MODULE、释放门控
- 检测手段：POCKET_ALIGNED 或 MAG_INDEX_OK 用霍尔或光电对射，接入 H1 与门。
- 系统响应：硬件与门拒绝释放，模式 B 无法完成；软件侧按 INDEX_FAIL(6) 或对齐失败升级软故障并禁 Mode B。
- 严重度：高
- 是否已有缓解：有。对齐开关接入 H1（架构 §6.5 H3、§6.6）。

## 二、电气类

### FM-08 FIRE_INHIBIT 短路到高

- 所属模块：安全输入，释放门控 H1
- 检测手段：**无检测手段**。架构 §6.7 提出双冗余触点交叉校验与「信号长时间无跳变」卡死诊断，尚未实现。
- 系统响应：fail-safe 丢失，短路会被当成许可，释放链可能被误允许。无自动响应。
- 严重度：极高
- 是否已有缓解：无有效缓解。下拉只防断线、掉电、接插件松脱，防不了短路到 3V3。对应风险 RSK-02。

### FM-09 I2C 总线卡死

- 所属模块：HAL、I2C0、MCP23017
- 检测手段：I2C 事务超时或 NACK；读取的慢速信号（MECH_RECOVERED、MAG_INDEX_OK 等）持续不变。
- 系统响应：慢速输入不可信。释放链与预载使能不依赖 I2C，硬件仍独立。I2C_BUS_HANG(13) 硬故障，
  置 FAULT 并保持硬件断开；PERIPH_INIT(1) 只覆盖上电初始化失败，运行期总线故障由前者单列。
- 严重度：高
- 是否已有缓解：部分。释放门控与预载使能不经 I2C（架构 §6.6）。

### FM-10 MCU 卡在输出高（RELEASE_CMD）

- 所属模块：MCU、释放执行器
- 检测手段：MCU 自身卡死无法自检，靠外部单稳态与看门狗。
- 系统响应：74HC123 单稳态把驱动时间钳成固定短脉冲，不会持续通电；看门狗超时 WATCHDOG(7) → SAFE。
  释放仍受与门 H1 约束。
- 严重度：高
- 是否已有缓解：有设计，待实物验证（架构 §6.6）。§6.9 第 9 条指出旧看门狗升级条件不可达，已改 esp_task_wdt。

### FM-11 电源跌落复位

- 所属模块：电源、MCU
- 检测手段：欠压复位（Brownout）；上电后重新走 BOOT → SAFE → HOME。
- 系统响应：上电瞬间释放链被硬件固定在禁止侧，预载使能断开（架构 §6.6、§6.10）；归零完成前不许动作。
- 严重度：高
- 是否已有缓解：有。硬件上电默认禁止侧，强制走 HOME 流程。

## 三、固件类

### FM-12 看门狗超时

- 所属模块：固件
- 检测手段：esp_task_wdt 或独立硬件看门狗。
- 系统响应：WATCHDOG(7) 软故障；超时直接进 SAFE（架构 §6.9 第 9 条）。
- 严重度：高
- 是否已有缓解：有。旧实现升级条件不可达，需按 §6.9 改成超时即升级。

### FM-13 状态机进入不可能组合

- 所属模块：cycle 状态机，区域 A 与区域 B
- 检测手段：双区域守卫矩阵在转移前校验；非法组合断言失败。
- 系统响应：拒绝转移并进 FAULT，软硬按是否安全相关分类；跨区守卫矩阵阻止区域 B 质量不足时进入
  PRELOAD 及之后。
- 严重度：高
- 是否已有缓解：有设计。双区域把非法空间从 11×7 收敛到守卫矩阵，待单元测试覆盖。

### FM-14 观测链路失效

- 所属模块：vision、取帧
- 检测手段：摄像头初始化失败；连续取帧失败计数达到 OBS_LINK_FAIL_N。
- 系统响应：OBS_LINK(5) 软故障 → FAULT → SAFE → HOME；禁止 AIM_ALLOWED 与 RELEASE。
- 严重度：中
- 是否已有缓解：有。代码已实现；架构 §6.9 第 12 条要求初始化失败走受限分支，不继续推进周期。

## 四、没有检测手段的失效模式

以下条目当前没有在线或自动检测手段，需要在后续设计里补传感或补判据：

- FM-03 膜片破裂：只有实验后目视与气密检查，运行中无在线检测。
- FM-04 弹性元件疲劳：靠离线 force-displacement 与寿命阶梯，运行中无在线检测。
- FM-06 双片：无专用传感器，只能靠人工与视频。
- FM-08 FIRE_INHIBIT 短路到高：无检测，且无有效缓解。
- FM-15 开环舵机非归零时段卡死：见下节，架构 §6.10 已指出判据不适用，当前无检测手段。

其中 FM-08 与 FM-15 同时属于风险台账里「没有有效缓解」的项。

### FM-15 开环舵机非归零时段卡死（补充条目）

- 所属模块：云台（pan、tilt）
- 检测手段：**无检测手段**。架构 §6.10 指出旧「速度长时间为零而 duty 高」判据在舵机上不适用；
  电流、母线电压跌落、到位超时、电流积分热模型等候选判据都还没标定。
- 系统响应：无自动响应。可能静默失位或停在错误指向继续动作；只有卡死发生在储能态或与机构卡死耦合时
  才升级 FAULT。
- 严重度：高
- 是否已有缓解：无。候选判据存在但未验证，标记该轴退化并禁 AIM_ALLOWED 的逻辑也依赖这些判据。
  对应风险 RSK-06。

## 五、缺口闭合记录

原先本节列的五个缺口都已在枚举末尾追加对应码，未改动既有取值：

| 失效模式 | 原缺口用途 | 对应新码 | 分级 |
|---|---|---|---|
| FM-03 膜片破裂 | 膜片或气路异常 | `MEMBRANE_RUPTURE`(10) | 硬 |
| FM-06 双片 | 供给双片 | `DOUBLE_FEED`(11) | 软 |
| FM-08 FIRE_INHIBIT 短路 | 安全输入通道不一致或卡死 | `FIRE_INHIBIT_SHORT`(12) | 硬 |
| FM-09 I2C 总线卡死 | I2C 运行期事务失败 | `I2C_BUS_HANG`(13) | 硬 |
| FM-13 不可能组合 | 状态机守卫违约 | `STATE_ILLEGAL`(14) | 硬 |

分级取值以 `faultSeverity()` 为准：`MEMBRANE_RUPTURE`、`FIRE_INHIBIT_SHORT`、`I2C_BUS_HANG`、
`STATE_ILLEGAL` 锁存，`DOUBLE_FEED` 可在清障后清除。原表给 FM-03、FM-06 的严重度建议写作「中」，
这里按代码的实际分级落实。

仍未闭合的是 FM-04 弹性元件疲劳与 FM-15 开环舵机非归零时段卡死，两者属于测量或标定问题，
没有对应码，先补检测手段。FM-08 的失效本身有了码，但检测手段仍未实现，运行期还发现不了。
