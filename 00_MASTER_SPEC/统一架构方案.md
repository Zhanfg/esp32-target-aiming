# 统一架构方案

MST-01 微型定向低能量脉冲平台的系统架构。这份文档取代此前把"视觉瞄准"与"脉冲炮头"分开描述的做法：
它们是同一件产品，分两期实现，先易后难。

版本 0.1.0。状态机与安全互锁部分由独立评审给出，见第 6 节。

---

## 1. 项目定义与分期

产品是一台 MCU 控制、火柴盒级、低能量、可模块化供给超轻软载荷的二维指向式快速机械脉冲执行平台。
整机由三块组成：**找目标的视觉**、**指向目标的云台**、**产生脉冲的机械核心**。

分两期做，原因只是难度递进，不是两个东西：

| 期 | 内容 | 状态 |
|---|---|---|
| 第一期 | 视觉定位、角度解算、标定、指向闭环、遥测与工具链 | 已完成（`00_MASTER_SPEC/`、`02_REQUIREMENTS/`、`05_FIRMWARE/`、`07_EXPERIMENTS/tools/`） |
| 第二期 | 两级串联失稳脉冲核心、柔性膜片、旋转供给盘、完整发射周期 | 待做 |

第一期交付的东西在第二期全部保留。第一期里的 `Transmitter` 抽象层就是第二期脉冲核心的挂载点。

## 2. 与 MST-01 规格书的关系

规格书是 `MST-01_Offline_Agent_Master_Spec_v2.0`，它是本产品的机械与执行规格，本文件是系统架构。

### 2.1 §34「不要研究目标检测」的处理

规格书 §34 禁止"研究目标检测、重做视觉系统"。那一段的原意是防止把项目重新发散成灭蚊器（§0.1 已说明
"打蚊子"只是尺寸与形态的类比）。本项目本来就不做蚊虫识别、翼频检测、生物特征分类。

视觉留作产品的目标来源，理由：规格书 §4 的系统架构图里有一格是"外部上层控制/目标坐标"，并注明
"具体来源不属于本项目范围"。那一格就是本项目的视觉部分，规格书把它画成外部是因为它当时只写炮头。
把两者合起来看，视觉属于产品内部。

为避免以后又把它当成违规，这里定下边界：

- 做：目标在画面中的位置、指向解算、标定。
- 不做：目标识别与分类、生物特征、任何与蚊虫相关的检测。

### 3.1 单片 MCU 的取舍

第一期的方案用双 MCU（视觉板 + 炮头板），前提是当时引脚不够。执行机构从 12V 减速电机改成微型舵机后，
电机闭环层整体删除，释放 11 个 GPIO（pan 电机 1/2/14、tilt 电机 21/47/48、STBY 38、编码器 39/40/41/42），
引脚预算翻了过来，单片即可覆盖全部信号。

选单片而不是双片：

- 火柴盒级产品，多一块板多一份体积、功耗与成本。
- 没有跨 MCU 协议，就没有协议失配、版本不一致、通信超时这三类故障。
- RELEASE 到膜片的时序在片内，不受总线延迟影响。

代价：视觉循环与发射时序共享一个 CPU。用非阻塞状态机 + 固定节拍控制环隔离，第二期的 PRELOAD/RELEASE
动作放在定时器中断或独立任务里，不排在视觉处理后面。这一条在第二期实现时必须验证，见第 9 节。

### 3.2 机械基线的模型预警

§3 的两级串联基线与 D-01 的冻结，前提是双级相对单级有实际价值。`04_SIMULATION/` 的纯软件模型（非实测）
在名义参数下给出不同倾向：C 相对 B 的膜片峰值速度只有约 18% 的增益，输入功接近翻倍，级序在刚度失配下会翻转。
模型没有干净命中 STOP-02，也不足以单方面推翻基线。决策当前状态、风险条目与两级实验的先验预测分别记在
`DESIGN_DECISION_LOG.md` 的 D-14、`RISK_REGISTER.md` 的 RSK-10、`TEST_PLAN.md` 的 B1/C1 通过标准处。
最终结论由 §16 的 A1/B1/C1 实验给出。

## 6. 状态机与安全互锁

### 6.1 做成双区域状态图，不拉平成一个枚举

11 个发射周期状态管的是"谁在储能、谁在释放"，7 个指向状态管的是"有没有看到目标、误差是否在死区"。
两件事天然并发：`PRELOAD` 期间可以仍处于 `TRACKING`，`READY` 期间也可以处于 `SEARCHING`。

塞进一个枚举会得到 11×7 的笛卡尔空间，其中绝大多数组合非法。用扁平枚举等于用缺席表达非法组合，
漏判一处就会进入"不可能状态"。发射链是安全相关代码，人工维护合法性矩阵正是最不该出错的地方。

所以分成两个区域，各自有转移表，跨区域用一张守卫矩阵约束。

**区域 A（发射周期）**：`BOOT SAFE HOME READY AIM_ALLOWED PRELOAD ARMED RELEASE RECOVER INDEX FAULT`
**区域 B（指向质量）**：`IDLE CALIBRATING SEARCHING TRACKING LOCKED CALIB_MODE`

旧 `AimState` 的落位：

| 旧状态 | 区域 A | 区域 B |
|---|---|---|
| `IDLE` | `READY` | `IDLE` |
| `CALIBRATING` | `HOME` | `CALIBRATING` |
| `SEARCHING` | `READY` | `SEARCHING` |
| `TRACKING` | `READY` | `TRACKING` |
| `LOCKED` | `READY` 或 `AIM_ALLOWED` | `LOCKED` |
| `CALIB_MODE` | `READY` | `CALIB_MODE` |
| `FAULT` | `FAULT` | 冻结 |

跨区域守卫矩阵（区域 B 决定区域 A 能走多远）：

| 区域 B | 允许的最高区域 A 状态 |
|---|---|
| `IDLE` / `SEARCHING` / `TRACKING` | `READY` |
| `LOCKED` | 全链 |
| `CALIBRATING` / `CALIB_MODE` | `READY`（禁止进入 `PRELOAD` 及之后） |

### 6.2 `AIM_ALLOWED` 与 `LOCKED` 的关系

`LOCKED` 是进入 `AIM_ALLOWED` 的入场条件，进入之后两者并存。`LOCKED` 是持续评估的质量谓词，
`AIM_ALLOWED` 是被授予并短暂保持的许可态。

依据是规格书自己的排序：§10.1 把 `AIM_ALLOWED` 放在 `READY` 之后、`PRELOAD` 之前。这个位置只有一种
合理解释，就是"指向已经可信，允许开始储能量"。若不依赖指向质量，它和 `READY` 就没有区别。

进入之后不能一丢 `LOCKED` 就退，否则一次丢帧就要在 `PRELOAD` 门口反复启停。落地规则：

- `AIM_ALLOWED → PRELOAD` 要求此刻仍为 `LOCKED`。
- `PRELOAD → ARMED` 不要求持续 `LOCKED`，但预载未完成时 `LOCKED` 丢失超过中止窗口就退回 `READY`
  并受控卸载（前提是机构支持安全卸载）。
- `ARMED → RELEASE` 是最后一道指向门，释放前一瞬重新确认 `LOCKED`，`ARMED` 停留期间指向子机继续跟。

`RELEASE` 不可逆，所以指向与发射许可之间必须存在一个耦合点，就是 `RELEASE` 门。完全解耦会留下
"许可还在、目标已经跑了"的窗口，那正是安全最不能接受的窗口。

### 6.3 标定期间的位置

`CALIBRATING` 与 `CALIB_MODE` 都限制在 `READY` 及以下，三层保证：

1. 软件守卫：区域 B 处于标定态时禁止 `READY → AIM_ALLOWED`。
2. 从 `ARMED` 或 `PRELOAD` 请求进入标定直接拒绝，只能在 `READY` 发起，且先卸载残余储能。
3. 硬件：标定期间软件主动把 `MECH_RECOVERED_N` 与 `FIRE_INHIBIT_N` 置到禁止侧，释放通道物理断开。

`CALIBRATING` 与 `CALIB_MODE` 的区别保留：前者是"标定数据无效，系统自动停留"，后者是"操作者手动建标定"。

### 6.4 `FAULT` 统一：锁存，但唯一出口经过 `HOME`

规格书 §11 Interlock 4 要求故障后必须重新 `HOME`；现有实现是置位后永不复位。统一成一句话：
**`FAULT` 锁存，不自动恢复，唯一清除路径是 `SAFE → HOME`，`FAULT → READY` 这条边不存在。**

- 引入故障码与严重级，对应 §19 的 `fault_code`。现在用自由文本事件不算故障码。
- 软故障（自检瞬时失败、观测链路异常、索引连续失败）允许 `FAULT → SAFE → HOME → READY`，
  其中 `HOME` 必须真实完成且参考开关全中。
- 硬故障（释放门控自检失败、机械卡死、参考开关矛盾）保持锁存，软件清除无效，必须断电或人工处理。
- 清除命令只把系统送到 `SAFE`，不直接到 `READY`。
- 硬件绑死：故障锁存器的复位条件接 `PAN_HOME & TILT_HOME & MAG_HOME`，机构没真回零位就复位不了。

### 6.5 硬转移与软转移

硬转移由物理通道决定，固件即使卡死或输出错误电平也无法完成。

| 编号 | 硬约束 | 实现 |
|---|---|---|
| H1 | 释放能量路径仅在 `FIRE_INHIBIT` 未断言、`EXTERNAL_ALLOW` 有效、`MECH_RECOVERED`、模式 B 时载荷对齐、`ARMED` 锁存、主使能有效时导通 | 物理与门串在释放执行器的供电回路 |
| H2 | 机构未复位时预载执行器无法被驱动 | 预载使能串 `MECH_RECOVERED_N` 常闭触点 |
| H3 | 模式 B 未对齐时释放无法完成 | 对齐开关接入 H1 与门；模式 A 用继电器旁路，默认旁路在安全侧 |
| H4 | 故障与急停锁存，未重新归零不能复位 | SR 锁存或自保持继电器，复位接 HOME 开关 |
| H5 | 超出机械限位 | 物理止挡 |
| H6 | 主电源急停 | 常闭蘑菇头直接串执行器供电，不经 MCU |

软转移是软件判定：`LOCKED` 判定、观测新鲜度、许可授予、预载到位、索引完成与重试、冷却与超时、
看门狗、故障码分类、模式选择。软转移可以当第一道闸，但不能是唯一一道。§10.4 反对的是用软件时序
顶替机械互锁，所以 H1 到 H4 必须真实存在。

### 6.6 四条互锁的硬件与软件分工

| 互锁 | 硬件 | 软件 |
|---|---|---|
| 1：`MECH_RECOVERED` 才准 `PRELOAD` | 常闭干接点串在预载驱动使能里，机构没复位就物理断驱动 | 迁移时复查该信号，做诊断与日志 |
| 2：`MAG_INDEX_OK` 才准 Mode B | 载荷对齐开关接入 H1 与门；模式 A 用继电器旁路成真 | `INDEX` 状态负责推进与判定，连续失败升级故障并禁 Mode B |
| 3：`FIRE_INHIBIT` 时 `RELEASE` 永远禁止 | 释放供电走高边负载开关，使能由与门树给出 | 发命令前读实际电平；`PRELOAD`/`ARMED` 期间监视上升沿，置位立即安全卸载 |
| 4：`FAULT` 后必须重新 `HOME` | 故障锁存器复位接三处 HOME 开关的与 | 故障码分类 + 唯一恢复路径 |

释放门控的与门树：

```
Q1 = AND( FIRE_INHIBIT_N, EXTERNAL_ALLOW, MECH_RECOVERED_N, POCKET_ALIGNED_or_MODE_A )
Q2 = AND( Q1, ARMED_LATCH, MCU_RELEASE_CMD, MASTER_ENABLE )
Q2 -> 负载开关使能
```

一片 74HC21（双 4 输入与门）级联即可覆盖。三个关键细节：

- 每个输入按极性加下拉或上拉，开路即安全侧。`Q2` 输出加下拉，浮空等于关断。
- 释放命令不直接由 GPIO 长驱动，中间加单稳态（如 74HC123）把驱动时间上限钳死。即使 MCU 卡在
  输出高，释放也只是一个固定短脉冲，不会持续通电。
- 负载开关用低边 N-MOSFET 串在回流路径，栅极带下拉；感性负载反并续流二极管，串自恢复保险丝。

### 6.7 `FIRE_INHIBIT` 与 `EXTERNAL_ALLOW`

| 信号 | 语义 | 有效方向 | 丢失或悬空 |
|---|---|---|---|
| `FIRE_INHIBIT` | 安全否决 | 主动拉高为允许，反转后进与门 | 禁止 |
| `EXTERNAL_ALLOW` | 上级许可 | 主动拉高为许可 | 拒绝 |
| `MCU_RELEASE_CMD` | 释放请求 | 主动拉高为请求 | 无请求 |

两者失效方向都指向安全，但来源不同：`FIRE_INHIBIT` 来自安全装置（舱门开关、光幕、外接急停、机械钥匙），
是可以随时否决的红灯；`EXTERNAL_ALLOW` 来自上层，是"我有目标、我授权这一发"的绿灯。

优先级由物理与门天然保证，任一红灯亮就否决。软件里先判 `FIRE_INHIBIT` 再判 `EXTERNAL_ALLOW`，
日志分别记录，便于事后区分是安全装置拦截还是上级撤回授权。

两条线都用下拉，只有被主动驱动为高才是许可，这样断线、掉电、接插件松脱全部落到禁止侧。信号被短路到
3V3 会失去 fail-safe，缓解办法是每个否决信号用两个冗余触点做双通道交叉校验，两路不一致就按禁止处理，
并把"信号长时间无跳变"作为卡死诊断。安全完整性做到什么程度需要实验确认，先按双通道设计留位置。

### 6.8 §30 五条 STOP 条件的落地

| STOP | 性质 | 响应 |
|---|---|---|
| STOP-01 单级无可测优势 | 实验结论 | 不进 `FAULT`。落成构建期机构变体常量加研究门控标志，禁启用双级相关功能 |
| STOP-02 双级更差 | 实验结论 | 同上，构建期回退单级，记录到 `10_FAILURE_ANALYSIS` |
| STOP-03 边界无稳定差异 | 实验结论 | 不进 `FAULT`。记录并关闭边界研究分支 |
| STOP-04 供给盘频繁卡料 | 运行期条件 | 进软故障。单次在 `INDEX` 重试并记 `jam`；连续失败或检出双片/错位则禁 Mode B、保留 Mode A。若发生在储能态且机构被顶死，升级 `FAULT` 并保持硬件断开 |
| STOP-05 成本超 ¥50 | 设计期预算 | 不进运行时。做成 BOM 校验门槛，设计评审告警，按 §21 顺序砍件 |

归类：STOP-01/02/03/05 是记录加降级，STOP-04 是运行期软故障且有升级条件。把所有研究结论都变成
`FAULT` 会让系统频繁锁死，反而削弱对 `FAULT` 的信任。

### 6.10 舵机化的安全设计

**上电归零**。PWM 舵机内部有电位计，指令脉宽对应绝对角，它自身是位置闭环的。所以归零在舵机上分两种
含义：设定物理基准，以及验证装配基准没偏。真实风险是上电前被外力拨偏或装配偏差，导致指令 0° 与
物理 0° 不一致。

1. 上电时释放链先被硬件固定在禁止侧，预载使能断开。归零完成前不许改变。
2. 每轴加参考开关（`PAN_HOME`、`TILT_HOME`），以限幅速度驱向参考方向等待触发。tilt 带重力负载，
   速度要慢，允许舵机先吃掉重力。
3. 开关触发后记为物理基准，退回一个已知角度作为 `HOME`。3 秒内不触发或触发后丢失即归零失败，
   进 `FAULT`，释放链保持断开，绝不进 `READY`。
4. 归零全程区域 A 处于 `HOME`，区域 B 处于 `CALIBRATING`。
5. 归零完成后再校验标定数据，有效才进 `READY`。

不建议省掉参考开关。装配偏差与上电前被动位移是真实存在的，而释放不可逆，一次基准错误就是打错方向。

**舵机选型建议**：优先用带总线反馈的舵机，而不是经典三线 PWM 舵机。§1.1 已把云台舵机排除在 ¥50 之外，
预算不是约束。总线舵机能直接回报位置、负载、温度，把失速检测从"猜"变成"读"，也让 `PAN_HOME`/`TILT_HOME`
退化成一次上电校验。这是舵机范畴内的实现选择，不违背已冻结的决策。

**失速检测**（无编码器时）：可用电流（舵机供电轨串 I2C 电流监控，走 I2C0）、母线电压跌落、到位时间
超时、电流时间积分的热模型。策略上检测到失速不进 `FAULT`，而是先停该轴、回退、重试一次，仍失败则把
该轴标记为退化并禁止进入 `AIM_ALLOWED`（指向不可信），释放链保持断开。只有失速发生在储能态或与机构
卡死耦合时才升级 `FAULT`。现有的"速度长时间为零而 duty 高"判据在舵机上不再适用。

**状态信号选型**：

| 信号 | 推荐 | 理由与注意 |
|---|---|---|
| `MECH_RECOVERED` | 微动开关常闭干接点 | 无源、可直接串进使能路径，最 fail-safe。要实测开关力不改变复位位置 |
| `STAGE1_STATE` / `STAGE2_STATE` | 霍尔锁存 | 无接触、数字锁存无 ADC 漂移、耐灰。**磁钢会扰动 snap 动力学**，必须做带靶/不带靶的 force-displacement 对照，靶附近件用 304 不锈钢（近无磁），别用 301 |
| `MAG_HOME` | 霍尔锁存 | 旋转件上贴小磁钢最简单，无需光路对齐 |
| `MAG_INDEX_OK` / 对齐 | 霍尔锁存或光电对射 | 对齐是安全相关，要接进与门 |
| `PAN_HOME` / `TILT_HOME` | 总线舵机位置加一个校验开关 | 有总线舵机时开关只做上电校验；PWM 舵机时开关是唯一基准 |

任何加到运动件上的传感靶都会改变动力学，§22.2 要求模块可拆可测，所以靶要能旋拧拆下，方便对照实验。
这一条必须实验确认，不能在设计上拍板。

### 6.11 最需要先验证的三件事

1. **释放路径的硬件门控能否在火柴盒体积内落地，且失败时确实落到禁止侧。** 整套安全设计的重心在 H1。
   先把释放执行器的原理定下来（电磁铁、sear 释放、还是预载反向），再证明与门可行、断线可测、
   MCU 卡死也放不出。验证方式：搭一块只有释放链和与门的小板，逐条故意断开输入、故意让 MCU 输出常高，
   确认释放无动作。这条不通过，后面所有状态机都是纸面。
2. **两级 snap 相对单级的实际动态价值。** 这是 §14、§30 STOP-01/02、§35 的核心问题。若单级相对普通
   膜片无可测优势，或双级更差，`PRELOAD → ARMED → RELEASE → RECOVER` 这条链与旋转供给盘的必要性都会塌掉。
   先做 §16 的 A1/B1/C1 对照，拿到可重复的 force-displacement 与脉冲时间曲线，再决定要不要把储能与
   释放链做进状态机。
3. **开环舵机的上电归零可靠性与失速可检测性。** 归零不可靠会让系统朝错误方向释放，失速检测不了会烧
   舵机或让云台静默失位。验证方式：测候选舵机参考开关的重复定位精度（多次上电的零位散布），做定角
   阶跃记录电流波形并标定堵转阈值，确认"电流超限且持续"不误报不漏报。

另有一条需要在 H1 定型时一并确认：**`ARMED` 态能否安全卸载**。如果机构一旦储能就只能释放、没有安全
dump 通道，`ARMED` 期间的任何中止都只能停在 `FAULT` 并保持硬件断开，这会显著改变状态机的可用性。
这个机械能力要在 A/B/C 阶段一并验证。

## 9. 待验证的高风险项

按 §1.1 的优先级（安全 > 可重复性 > 可靠性 > 小型化 > 低成本 > 输出强度）排序。

1. **视觉循环与发射时序的隔离**。单片方案下两者共用一个 CPU。如果 `PRELOAD`/`RELEASE` 的时序被视觉
   处理拖后，轻则脉冲不一致，重则机构停在中间态。第二期必须实测最坏情况下的时序抖动。
2. **舵机开环的指向精度**。失去编码器后，舵机的死区、回差、温漂都直接进入瞄准误差。要在 MST-01A
   阶段就量出静态指向重复性，确认还能不能把目标锁在画面死区内。
3. **`MECH_RECOVERED` 的判定可靠性**。这是 Interlock 1 的唯一依据，如果它误报为真，系统会在机构未复位时
   进入 PRELOAD。用一个慢速 I2C 扩展器读它是否够快、够可靠，要在 MST-01B 验证。
