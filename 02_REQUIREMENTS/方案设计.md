# 方案设计

这份文档是项目的设计基准。模块接口、坐标系约定、算法公式以这里为准。改了设计就要同步改这里，
不然 C++ 固件和 Python 参考实现会失配。

版本 0.1.0，设计已锁定，待实施。

## 1. 目标与范围

给定图像（离线坐标标注数据或摄像头实时帧），让 ESP32-S3 在本地完成目标定位与瞄准解算，
驱动双轴电机舵盘把目标锁在画面中心，并可驱动一个发射器。

做这些：

- 目标检测与定位
- 像素到角度的几何解算
- 滤波与轨迹预测
- 提前量计算
- 双环 PID 电机闭环
- 编码器反馈
- 限位与安全
- 遥测与标定工具

不做这些：

- 发射器的具体型号与物理实现，只提供抽象接口和占位实现
- 目标识别（分类、身份判定），只关心目标在画面里的位置

两条硬约束：

1. 本地闭环。运行时不许依赖 PC，PC 只用于开发期的算法验证和标定。
2. 实时性。单帧处理加控制回路必须在预算内完成，不允许阻塞等待。

## 3. 硬件选型

| 部件 | 选型 | 理由 |
|---|---|---|
| 主控 | ESP32-S3 N16R8，16MB Flash / 8MB OPI PSRAM | 摄像头驱动成熟；PSRAM 够放图像帧和中间缓冲；双核可以把视觉和控制分到两个核 |
| 摄像头 | OV2640（主）、OV5640（备） | 前者驱动最稳，后者分辨率和成像更好，共用一套 esp32-camera 驱动 |
| 电机 ×2 | JGB37-520 12V 有刷减速电机，带霍尔编码器 | 扭矩够带舵盘；有刷闭环比无刷简单一个数量级；自带编码器省掉外置测速 |
| 驱动 | TB6612FNG | 一片双路 H 桥同时驱 pan 和 tilt；体积小，逻辑简单，带待机控制 |
| 反馈 | ESP32 PCNT 外设正交解码 | 硬件计数不占 CPU，四倍频提高分辨率 |
| 发射器 | 抽象接口 + 电机/继电器占位实现 | 型号未定，先把耦合切开，以后可替换 |

### 3.1 为什么选有刷

无刷配 FOC（SimpleFOC 之类）确实更平滑、带宽更高，代价是需要电流采样电路、更复杂的换相
和观测器代码，调试周期也长。这个项目的难点在视觉和解算，不在电机。用有刷加编码器把控制层
做扎实，风险最低。接口层已经抽象出 `MotorDriver` 和 `Axis`，将来换无刷只替换驱动实现。

### 3.2 供电与接地

- 电机 12V 和逻辑 3.3V/5V 分开供电，只在一点共地。
- 电机侧并一个大电解电容，470µF 起步，用来吸收换向尖峰。不加的话 ESP32 会反复复位。
- TB6612FNG 的 VM 接 12V，VCC 接 3.3V，STBY 交给 MCU 控制，急停时拉低即可断电。
- 编码器输出是开漏时注意电平，必要时串 1kΩ 限流。

## 4. 坐标系与角度约定

这一节最容易出错。任何裸的角度相减都是 bug。

### 4.1 图像与相机坐标系

- 图像坐标：x 向右，y 向下，原点在左上角，单位 px。
- 相机坐标系：X 右，Y 下，Z 前（光轴正向）。
- 归一化坐标：`x_n = (u - cx) / fx`，`y_n = (v - cy) / fy`。

### 4.2 角度定义

| 量 | 定义 | 正方向 |
|---|---|---|
| `bearing` 方位角 | `atan2(X, Z)` | 向右为正，俯视顺时针 |
| `elevation` 俯仰角 | `atan2(-Y, sqrt(X² + Z²))` | 向上为正 |
| `pan` 舵盘水平角 | 水平旋转 | 向右转为正 |
| `tilt` 舵盘俯仰角 | 摄像头抬角 | 向上抬为正 |

### 4.3 正反变换

像素到角度。先取归一化射线 `ray = (x_n, y_n, 1)`：

```
bearing   = atan(x_n)
elevation = atan2(-y_n, sqrt(x_n² + 1))
```

角度回像素，与上式严格互逆：

```
x_n = tan(bearing)
y_n = -tan(elevation) / cos(bearing)
u   = x_n · fx + cx
v   = y_n · fy + cy
```

### 4.4 单位后缀

`_rad`、`_deg`、`_ms`、`_px`、`_s`、`_dps`（度每秒）。内部计算用弧度，模块之间传度。长度用 mm。

## 5. 镜头畸变模型

用标准的径向切向模型，参数 k1、k2、p1、p2、k3：

```
r² = x² + y²
radial     = 1 + k1·r² + k2·r⁴ + k3·r⁶
x_dist = x·radial + 2·p1·x·y + p2·(r² + 2x²)
y_dist = y·radial + p1·(r² + 2y²) + 2·p2·x·y
```

反畸变用定长迭代，五次起步：

```
x₀ = x_dist
xₙ₊₁ = (x_dist - tangential(xₙ)) / radial(xₙ)
```

选迭代不选解析解，是因为在正常畸变范围内迭代收敛快、数值稳定，还能直接向量化。细节见
[标定与几何推导](标定与几何推导.md)。

## 7. 算法链路

### 7.1 完整链路

```
像素观测 (u, v)
  │
  ├─① 畸变校正 ────────────────► 归一化坐标 (x_n, y_n)
  ├─② 像素到角度 ──────────────► (bearing, elevation)
  ├─③ 双轴 Kalman 滤波 ────────► (θ̂, ω̂)，含离群门控
  ├─④ 计算提前量 t_lead
  ├─⑤ 外推至 now + t_lead ─────► 预测角
  ├─⑥ 标定仿射加零点偏移 ──────► pan/tilt 目标角
  ├─⑦ 限位夹紧，环绕感知
  └─⑧ 角速度限幅 ──────────────► 输出给控制层
```

### 7.2 提前量模型

激光直瞄没有弹丸飞行时间，提前量只来自执行机构滞后。

```
t_lead = t_latency + t_settle + max(0, (|Δθ| - deadband) / ω_max)
```

| 符号 | 含义 |
|---|---|
| `t_latency` | 指令下发到电机开始响应的延迟，含驱动、通信、滤波 |
| `t_settle` | 机械稳定时间，含减速箱间隙和结构弹性引起的振荡衰减 |
| `Δθ` | 当前角度误差，用 shortest_delta 算，不能裸减 |
| `ω_max` | 该轴最大角速度，受 MAX_SLEW_DPS 和电机能力约束 |
| `deadband` | 死区，避免抖动 |

外推默认一阶。速度高且加速度估计可信时升到二阶，二阶必须带阻尼：

```
θ_pred = θ̂ + ω̂ · t_lead                          (一阶)
θ_pred = θ̂ + ω̂ · t_lead + ½·â · t_lead²          (二阶，â 受限幅与阻尼)
```

### 7.3 门控

阈值分割在光照变化、遮挡、背景同色时会蹦出跳变离群点。门控是第一道防线，残差超过阈值
直接拒绝该观测。第二道是 TrackLossDetector，连续 N 帧没有有效观测就降级到 SEARCHING。

### 7.4 滑行

短暂丢帧时立即停机反而会让舵盘来回抖。做法是沿用滤波预测滑行，超过 `coast_timeout_s`
才判定丢失进入搜索。滑行期间预测必须做幅度钳制，不能无界外推。

## 8. 控制链路

```
目标角 θ_tgt ──►[位置环 PID]──► ω_cmd ──►[速度环 PID]──► duty ──►[TB6612]──► 电机
                    ▲                        ▲                                  │
                    │                        │                                  │
               θ_meas（编码器角度）      ω_meas（编码器差分）◄────────────────────┘
```

外环，位置：

```
e_θ   = shortest_delta(θ_tgt, θ_meas)     // 环绕感知，禁止裸减法
ω_cmd = Kp_p·e_θ + Ki_p·∫e_θ dt + Kd_p·de_θ/dt
```

内环，速度：

```
u = Kp_v·(ω_cmd - ω_meas) + Ki_v·∫ + Kd_v·d/dt
```

需要的机制和原因：

| 机制 | 原因 |
|---|---|
| 积分限幅，输出饱和时停止积分 | 目标不可达时积分项会无限累积，反向时严重超调 |
| 微分项一阶低通 | 编码器差分的量化噪声会被微分放大，不滤会抖 |
| 死区 | 编码器分辨率和机械间隙让误差无法归零，不设死区会持续嗡鸣 |
| 占空比上限 | 保护电机和 H 桥，防止堵转烧毁 |
| duty 变化率限制 | 抑制电流冲击和机械冲击 |
| 软限位 | 防止撞机械限位 |

### 8.1 编码器换算

```
COUNTS_PER_OUTPUT_REV = PPR × 4 × GEAR_RATIO
θ_deg = encoder_count / COUNTS_PER_OUTPUT_REV × 360
```

以 JGB37-520 为例，PPR 取 11、减速比 1:30，则 `11 × 4 × 30 = 1320 counts/rev`，
分辨率 `360 / 1320 ≈ 0.273°/count`。

PPR 和减速比必须按实物确认。JGB37-520 不同批次有 11 和 13 两种 PPR，减速比也有 30、56、90
多种。填错会让角度和速度整体比例偏。

## 9. 360° 环绕能力的预留

需求是先用 ±180° 有限角度，代码里预留 360° 环绕能力。三个落点，缺一不可：

1. `math/angle_utils` 同时提供环绕和线性两套语义。`angleDiffDeg` 走最短环绕分支，
   `angleDiffDegLinear` 走线性分支，另有 `angleWrap360`。
2. `config.h` 里的 `ANGLE_WRAP_360_ENABLED` 开关，默认 0。开启后限位判定和角度比较
   自动切到环绕分支。
3. `control/` 和 `calibration/` 里所有角度比较与相减必须经由 `angle_utils`。
   代码评审时把裸减法视为阻断性缺陷。

将来换滑环上 360° 时，把开关置 1 再处理线缆即可，控制算法不用重写。

## 10. 安全设计

| 风险 | 对策 |
|---|---|
| 发射器误触发 | 只在 LOCKED 状态且显式 arm 后才允许 fire；setup 期间绝不使能 |
| 电机堵转烧毁 | 占空比上限加电流预算，再加堵转检测（速度长时间为零而 duty 高） |
| 撞机械限位 | 软限位加接近限位时限幅，at_limit 标志上报 |
| 主循环阻塞 | 看门狗监控单次 loop 耗时，超预算就降帧并记录，禁止长 delay |
| 摄像头失败 | 状态机进 FAULT，电机停转，发射器断开 |
| 供电跌落复位 | 电机侧大电容加分供电加单点共地 |
| 失控 | turretEmergencyStop 和 transmitter.emergencyStop 无条件立即生效 |

## 12. 标定流程

1. 内参标定。棋盘格在 PC 端用 OpenCV 求 fx、fy、cx、cy 和畸变系数。这一步是离线工具，
   不进固件。
2. 轴角标定。在画面里选若干已知像素点，把舵盘转到该点居中，记录像素和当时的 pan、tilt。
3. 解算仿射。用 `calibrationSolveAffine` 做最小二乘，求出 2×3 仿射矩阵。
4. 校验。拿没参与解算的点算残差，输出 RMSE。超阈值就回第 2 步补点，优先补视野边缘。
5. 持久化。结果写进 NVS，setup 时加载，失败进 CALIBRATING。

## 13. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 复杂背景下分割不稳 | 观测抖动或丢失 | 门控加预测滑行，可切换 ROI 和阈值；必要时上轻量检测模型 |
| 机械间隙引起极限环振荡 | 抖动，精度差 | 死区加微分滤波，或换小间隙减速箱 |
| 12V 电机干扰导致 MCU 复位 | 系统不稳 | 分供电、单点共地、大电容，必要时光耦隔离 |
| PSRAM 带宽成为瓶颈 | 帧率不达标 | 降分辨率，降采样后只留 ROI，转灰度 |
| PPR 或减速比填错 | 整条角度链偏 | P0 阶段先做转一圈数 count 的验证程序 |
| 发射器安全 | 人身伤害 | 第 10 节的安全设计强制执行 |
