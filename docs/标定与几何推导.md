# 标定与几何推导

从像素到舵盘角的完整数学链路，含推导、数值示例和误差预算。
C++ 固件（`firmware/src/calibration/`）和 Python 参考实现（`algo_reference/src/aim/geometry.py`）
必须与这份文档一致。

## 1. 符号与坐标约定

| 符号 | 含义 | 单位 |
|---|---|---|
| `u, v` | 像素坐标，原点左上角，u 向右，v 向下 | px |
| `fx, fy` | 焦距，像素单位 | px |
| `cx, cy` | 主点坐标 | px |
| `x_n, y_n` | 归一化像面坐标，无畸变 | 无量纲 |
| `bearing` | 方位角，`atan2(X, Z)`，向右为正 | rad |
| `elevation` | 俯仰角，`atan2(-Y, sqrt(X²+Z²))`，向上为正 | rad |
| `k1,k2,k3` | 径向畸变系数 | 无 |
| `p1,p2` | 切向畸变系数 | 无 |
| `pan, tilt` | 舵盘水平角与俯仰角 | ° |

相机坐标系是 X 右、Y 下、Z 前。Y 向下是 elevation 定义里带负号的原因。

## 2. 针孔模型

归一化像面：

```
x_n = (u - cx) / fx
y_n = (v - cy) / fy
```

对应的射线方向取 Z = 1 平面：

```
ray = normalize( (x_n, y_n, 1) )
```

## 3. 畸变模型，正向

真实镜头会让像点偏离理想位置。用标准径向切向模型：

```
r² = x_n² + y_n²

radial      = 1 + k1·r² + k2·r⁴ + k3·r⁶
x_distorted = x_n·radial + 2·p1·x_n·y_n + p2·(r² + 2·x_n²)
y_distorted = y_n·radial + p1·(r² + 2·y_n²) + 2·p2·x_n·y_n
```

径向项 `x·radial` 来自透镜曲率，表现为画面边缘的桶形或枕形弯曲。

切向项含 p1、p2，来自镜头与传感器装配不平行。

## 4. 反畸变

相机给出的是畸变后坐标，我们需要畸变前的理想坐标，也就是求第 3 节的逆映射。

这个映射没有解析闭式解，用不动点迭代：

```
x₀ = x_distorted
重复 N 次：
    r² = x² + y²
    radial = 1 + k1·r² + k2·r⁴ + k3·r⁶
    Δx = 2·p1·x·y + p2·(r² + 2x²)
    Δy = p1·(r² + 2y²) + 2·p2·x·y
    xₙ₊₁ = (x_distorted - Δx) / radial
    yₙ₊₁ = (y_distorted - Δy) / radial
```

选迭代而不选解析解，有三个原因。正常畸变范围内（|k1| < 0.5、|k2| < 0.2）五次迭代就能收敛到
1e-9 量级。解析解比如直接求三次方程的根，在 r 趋近 0 时数值不稳定，迭代法天然避开这个区域。
迭代写法可以直接向量化，也方便在 MCU 上做定点实现。

收敛判据是迭代前后 `|Δx| + |Δy| < 1e-9`，或者达到最大迭代次数，取 5 到 10 次。

## 5. 像素到角度

反畸变后拿到理想归一化坐标 `(x_n, y_n)`：

```
bearing   = atan(x_n)
elevation = atan2( -y_n, sqrt(x_n² + 1) )
```

推导过程。相机坐标系下 Z = 1 的射线是 `(x_n, y_n, 1)`：

- `bearing = atan2(X, Z) = atan2(x_n, 1) = atan(x_n)`
- `elevation = atan2(-Y, sqrt(X² + Z²)) = atan2(-y_n, sqrt(x_n² + 1))`

elevation 的分母为什么是 `sqrt(x_n² + 1)` 而不是 1：投影到 XZ 平面后 Z 分量还是 1，
X 分量是 `x_n`，两者合成模长就是 `sqrt(x_n²+1)`。

## 6. 角度到像素

```
x_n = tan(bearing)
y_n = -tan(elevation) / cos(bearing)

u = x_n · fx + cx
v = y_n · fy + cy
```

验证互逆性。正向代入 `bearing = atan(x_n)` 显然成立。

elevation 这一侧，令 `t_e = tan(elevation)`：

```
-tan(e)/cos(b) = -(sin e / cos e) / cos b = -sin e / (cos b · cos e)
```

反过来，由 `x_n = tan b` 和 `y_n = -tan e / cos b` 推：

```
elevation = atan2(-y_n, sqrt(x_n²+1))
          = atan2( tan e / cos b , sqrt(tan²b + 1) )
          = atan2( tan e / cos b , 1/cos b )        // sqrt(tan²b+1) = 1/cos b，b ∈ (-π/2, π/2)
          = atan( tan e )
          = e
```

所以往返误差应该在机器精度量级。单元测试里这一条按 1e-9 断言。

## 7. 数值示例

OV2640 跑 640×480，取 `fx = fy = 480`、`cx = 320`、`cy = 240`，畸变系数全为零。

正算，像素 `(400, 180)`：

```
x_n = (400 - 320) / 480 =  0.166667
y_n = (180 - 240) / 480 = -0.125000

bearing   = atan(0.166667)                       = 0.165149 rad = 9.462°
elevation = atan2(0.125, sqrt(0.166667² + 1))
          = atan2(0.125, 1.013793)               = 0.122685 rad = 7.029°
```

反算，`bearing = 9.462°`、`elevation = 7.029°`：

```
x_n = tan(9.462°)              =  0.166667
y_n = -tan(7.029°)/cos(9.462°)
    = -0.123305 / 0.986410     = -0.125000
u = 0.166667 · 480 + 320       =  400.0
v = -0.125000 · 480 + 240      =  180.0
```

往返一致。这组数字直接拿去做单元测试的回归基准。

## 8. 角度到舵盘角

理论上 pan、tilt 应该等于 bearing、elevation 加零点偏移。实际有几种偏差：

- 摄像头光轴与舵盘旋转轴不重合，安装偏差
- 镜头与舵盘坐标轴没对齐，有滚转或俯仰残留
- 电机零点和机械零点不同

这些误差在小角度范围内可以用一个 2×3 仿射矩阵建模：

```
[ pan  ]   [ a11 a12 a13 ]   [ bearing ]
[ tilt ] = [ a21 a22 a23 ] · [ elevation ]
                              [    1    ]
```

即 `q = A · p̃`，其中 `p̃ = (bearing, elevation, 1)ᵀ`，`q = (pan, tilt)ᵀ`。

用仿射而不是直接相等，是因为仿射同时吸收了尺度、交叉耦合、旋转、平移四类误差。
如果标定后残差还是偏大，说明系统里有非线性没被处理掉，多半是镜头畸变没校正好。
这时候该回第 3 节检查畸变系数，而不是往上加多项式阶数。

## 9. 仿射矩阵的最小二乘解算

给定 N 组标定对应点 `(p̃ᵢ, qᵢ)`，堆成矩阵：

```
P = [ p̃₁ p̃₂ … p̃_N ]   (3 × N)
Q = [ q₁  q₂  … q_N ]   (2 × N)
```

目标是 `min ‖Q - A·P‖_F`。令梯度为零，得正规方程：

```
A = Q · Pᵀ · (P · Pᵀ)⁻¹
```

实现上有几点要注意。

`P·Pᵀ` 是 3×3 矩阵，求逆代价可以忽略。数值上更稳的做法是用 `lstsq`（QR 或 SVD），
不要显式求逆。

标定点数至少 3 个才有唯一解。工程上前视建议 9 个以上，摆成 3×3 网格，用来平抑手抖和
像素量化噪声。

标定点要铺满视野。全挤在画面中央的话，外推区域的误差会急剧放大，矩阵接近病态。

## 10. 标定流程

```
① 内参标定（PC 端离线，OpenCV，不进固件）
   └─ 棋盘格多姿态拍摄，求 fx, fy, cx, cy, k1, k2, p1, p2, k3
   └─ 写入 config.h 或 NVS

② 轴角标定（在真实设备上采集对应点）
   └─ 在画面中选定一个已知像素点
   └─ 手动或半自动把舵盘转到该点居中
   └─ 记录 (像素, 当前 pan, tilt)

③ 解算
   └─ 像素转 bearing/elevation，见第 5 节
   └─ 用第 9 节解出 A

④ 校验
   └─ 用没参与解算的留出点算 RMSE
   └─ 超阈值回 ② 补点，优先补视野边缘

⑤ 持久化
   └─ 写入 NVS，setup 时加载，失败进 CALIBRATING
```

校验指标：

```
RMSE = sqrt( mean( ‖A·p̃ᵢ - qᵢ‖² ) )      // 单位：度
```

| RMSE | 评价 |
|---|---|
| < 0.2° | 优秀，可直接用于静态打靶 |
| 0.2° ~ 0.5° | 可用，满足初版目标 |
| 0.5° ~ 1.5° | 偏大，检查光轴与轴系对齐，检查畸变系数 |
| > 1.5° | 不可用，系统存在结构性误差 |

## 11. 误差预算

各环节对最终指向误差的贡献，下面是初版估算，需要实测修正。

| 来源 | 量级 | 说明 |
|---|---|---|
| 像素量化 | 小 | 亚像素质心能压到 0.1 px 以下 |
| 分割质心偏差 | 主导 | 阈值分割受光照影响，目标边缘不稳 |
| 内参畸变残余 | 中 | 标定不准会在视野边缘放大 |
| 仿射拟合残差 | 小到中 | 由标定点分布决定 |
| 机械间隙 | 主导 | 减速箱反向空程 |
| 编码器分辨率 | 小 | 例：1320 counts/rev 对应 0.273°/count |
| 控制稳态误差 | 小 | 有积分项能消除，但受死区限制 |

分割稳定性和机械间隙是两个主导项。把力气花在这两处，收益比追求更高分辨率的编码器大得多。

减小机械间隙影响的手段：

1. 单向趋近。让跟踪总是从同一侧接近目标角，避开反向空程。
2. 速度模式跟踪。视觉伺服里用速度环而不是位置环，天然不来回穿越齿隙。
3. 换低背隙减速箱。JGB37-520 标准款背隙偏大，精度要求高就得换型号。

## 12. 移植到 C++

| 事项 | 做法 |
|---|---|
| 浮点精度 | ESP32-S3 有 FPU，用 float 即可；角度累积量用 double |
| 三角函数 | atan2f、tanf 已经在 ROM 里，速度可接受；不要在中断里调用 |
| 迭代次数 | 反畸变固定 5 次，不要用 while，保证最坏执行时间可预测 |
| 查表优化 | 帧率高时可以对像素到角度做 LUT 加双线性插值 |
| 符号一致性 | y 轴向下的约定在 C++ 里同样成立，不要顺手改成向上 |
| 角度环绕 | 角度比较一律走 angle_utils，见[方案设计](方案设计.md)第 9 节 |
